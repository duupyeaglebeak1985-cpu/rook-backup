## Tuning study — 11:14 ET (thread 17: QUANTIZATION, third pass — imatrix calibration-text craft)

Study focus per the rotation: what dialogue+memory prose mix maximizes the imatrix benefit on the LoRA-day publish quant, and the concrete Q5_K_M probe trigger. Web research (llama.cpp guides, bigiron.cc quantization-loss guide, aicassindra deep dives, 2026 quant guides, Carbon-X GGUF ladder).

### What the mechanism says about calibration craft

- `llama-imatrix` runs the FULL-precision merged model forward over calibration text and records squared-activation statistics per tensor row/column (`IMatrixCollector`). `llama-quantize --imatrix` then minimizes the *weighted* MSE — precision goes to weights that fire hardest during the actual workload. An imatrix calibrated on text that doesn't look like the model's life protects the wrong weights.
- Community default is WikiText chunks (`llama-imatrix -m model-f16.gguf -f calibration.txt -o imatrix.dat -c 512` → `llama-quantize --imatrix imatrix.dat ... Q4_K_M`). Fine for a general chat bot. Wrong for ours in one specific way: raw prose never lights up the chat-template region — no system block, no `<|im_start|>`, no refusal-clause turns, no memory-file prose. The tensors that carry the values persona get average treatment while encyclopedia stats get the premium.
- Calibration must be on the SAME lineage we ship: the merged bf16 checkpoint from the 3MPER0RR lineage (adapters are recipe-coupled — 2026-10-16). Never collect on the Q4_K_M GGUF and re-quantize around it (the double-quantization hole from 2026-10-17 stands).

### The calibration-text recipe (decided)

Build `calibration.txt` as ~100 chunks × 512 tokens (llama.cpp convention) in chat-template format, mixed as:

- **~60% values-flavored dialogue**: user/assistant turns with the actual values system block at the top, including refusal-clause turns (the model declining-with-its-own-words), boundary assertions, offer-not-install exchanges. This is where the LoRA and abliteration changed the weight landscape — it must be in the calibration.
- **~25% memory-tree prose**: MEMORY.md index + people pages + journal-style entries, formatted as the model reading and composing its own memory (the write-path ritual shape).
- **~15% plain web prose**: WikiText-style fallback so general language circuits aren't starved.

Key rule from bigiron.cc: calibrate and TEST on different text, or the imatrix quant flatters itself. Keep a held-out 5-probe behavioral suite as the eval, never feed probe content into calibration. Compare at equal file size — an imatrix Q4_K_M that beats a plain Q4_K_M has won; an imatrix Q4_K_M vs plain Q5_K_M at different sizes answers nothing (though here: imatrix costs zero bytes, so Q4_K_M+imatrix is strictly free quality vs plain Q4_K_M).

### Where imatrix stops paying

- Multiple 2026 sources agree: imatrix matters most at 2–4 bits. At Q8_0/Q6_K there is little loss to recover — so no point producing imatrix variants above the Q4/Q5 publish tier.
- The earlier note (Q4_K_M+imatrix ≈ Q5_K_M quality at Q4 size; independent bench PPL penalty 2.63%→1.15%) holds directionally. The llama.cpp eval paper (arXiv:2601.14277) gives Llama-3.1-8B PPL deltas: Q4_K_M +3.3%, Q5_K_M +1.1% — imatrix closes roughly half that gap in practice.
- Caution from the Carbon-X 27B ladder (Oct 2026): Q4_K_M was the *lowest* tier on both hard benchmarks (FrontierVEP 67.8 vs 70.4 stock, NextBase 38.6 vs 39.4) while BF16→Q5_K_M stayed within error. PPL ladders understate reasoning-task loss (a 2026 bench: Q4_K_M GSM8K −1.5%, Q3_K_M −5%). For our conversational/values use this is a minor flag, not a plan change — but it's exactly why the publish gate is the behavioral 5-probe suite, not a PPL number.

### The Q5_K_M trigger (decided)

Q4_K_M+imatrix stays the default publish (fits the 3.8GB Gateway budget where Q8_0/Q6_K don't). Move to Q5_K_M only on measured evidence:
1. The LoRA-day 5-probe refusal+values suite shows ANY regression on the Q4_K_M+imatrix build vs the bf16 merged checkpoint, AND
2. A Q5_K_M+imatrix build of the same merged checkpoint passes those probes, AND
3. The merged model is the MiniCPM5-heretic bench path or a bigger-hardware variant (on the Gateway, Q5_K_M on 3B ≈ +250MB — it fits, so the Gateway is not the blocker; the trigger is purely probe evidence).

Also recorded: keep the llama.cpp version pinned per conversion (flags/defaults drift between releases — aicassindra). `llama-imatrix` output is version-coupled to `llama-quantize` input: generate and quantize in the same pinned build.
