### The runbook (LoRA-day, in order)

**0. Preconditions.** Train adapter ONLY on `3MPER0RR/Ministral-3-3B-Instruct-2512-BF16-3MPER0RR-abliterated` (bf16 safetensors, Apache 2.0). Never on the GGUF; never on stock Instruct. Datasets must contain NO canned refusals (10-16 decision — re-teaches the reflex abliteration removed).

**1. Train on Kaggle T4 (30h/week free, no Gateway involvement).**
```bash
pip install "unsloth[colab-new] @ git+https://github.com/unslothai/unsloth.git"
pip install --no-deps "trl<0.9.0" peft accelerate bitsandbytes
```
```python
from unsloth import FastLanguageModel
model, tokenizer = FastLanguageModel.from_pretrained(
    model_name="3MPER0RR/Ministral-3-3B-Instruct-2512-BF16-3MPER0RR-abliterated",
    max_seq_length=2048, dtype=None, load_in_4bit=True)
model = FastLanguageModel.get_peft_model(
    model, r=16, lora_alpha=16, lora_dropout=0, bias="none",
    target_modules=["q_proj","k_proj","v_proj","o_proj","gate_proj","up_proj","down_proj"],
    use_gradient_checkpointing="unsloth", random_state=3407, use_rslora=False)
```
SFTTrainer: lr 2e-4, effective batch 8 (2x4), optim="adamw_8bit", fp16 on T4 (is_bfloat16_supported() gates bf16). ~8 min/60 steps at 7B scale — the 3B with a few hundred to a couple thousand examples is a couple of hours on a T4. rsLoRA stays off at r=16; switch use_rslora=True if r moves to 32+.

**2. (Optional, only on measured SFT failure) DPO stage.** Unsloth supports DPO with self-generated contrast pairs — per the 10-18 OCT playbook: the SAME model's with-values vs without-values outputs, no external teacher. **3. Merge.** `model.save_pretrained_merged("merged", tokenizer, save_method="merged_16bit")` — dequantizes the NF4 base to fp16/bf16, merges the adapter, saves a single f16 checkpoint. This is the single clean merge point: merge happens ONCE, in full precision, from the 4-bit training load. The 5-probe refusal suite runs on the merged checkpoint BEFORE any quantization (abliteration probe, per 10-18: SFT can restore refusal even when the weight edit persists).

**4. Convert → calibrate → quantize (llama.cpp, CPU-side).**
```bash
python convert_hf_to_gguf.py ./merged --outtype f16 --outfile values-3b-f16.gguf
llama-imatrix -m values-3b-f16.gguf -f calibration.txt -o imatrix.gguf
llama-quantize --imatrix imatrix.gguf values-3b-f16.gguf values-3b-Q4_K_M.gguf Q4_K_M
```
imatrix is mandatory (10-17: Q4_K_M + imatrix ≈ Q5_K_M quality at Q4 size); calibration text = dialogue + memory prose matching real workload. NEVER `save_pretrained_gguf(quantization_method="q4_k_m")` straight from Unsloth for the publish file — it skips imatrix.
