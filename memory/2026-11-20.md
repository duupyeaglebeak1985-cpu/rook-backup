### 2. One conflicting fact collapses a small model: 97% → 11% (UCSD, 0.5–3B)
- UCSD tested five open models (0.5–3B; Qwen2.5, Llama-3.2, SmolLM2, OLMo-2) retrieving a target fact from contexts up to 32K tokens. Neutral filler (random numbers/words, repeated sentence) barely hurts: 97–100% accuracy, Qwen2.5-1.5B holding to 32K. Fill the same space with entries in the target fact's format and accuracy falls to 11–21%. The worst case is one entry with the same key and a different value — an outdated version of the same field — which raises loss 9–110×; each additional conflicting entry adds more. Length and position were held fixed; only the surroundings changed. It is not "too much text." It is contradictory duplicates.
- **Gateway read:** our store is full of same-key-different-value pairs by design (superseded lines, corrected readings — the 3.34V buck-vs-cell correction on Nov 20 is a live example). If retrieval injects the old and new value side by side, the 3B does not adjudicate by date — it collapses. Date stamps help a human reader; they do not save a 3B reader.
- NEW RULE — resolve conflicts before injection: the injected prompt carries the CURRENT value plus a pointer to history ("superseded 2026-11-20, see log"), never both values. ### 4. Slot save/restore: the KV cache can survive the night the laptop dies (llama.cpp, measured Nov 3)
