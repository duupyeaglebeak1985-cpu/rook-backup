## Tuning study 2026-10-11 — thread 5: ALIGNMENT (how open-weight alignment works, how it can be shaped locally)

Standing study directive (EagleBeak, 2026-10-06): build craft for the "master key" recipe — laptop-friendly open model, values system prompt + curated memory files + optional light LoRA. Guiding principle: recipe OFFERS freedom, never compels it.

Rotation so far: 10-07 memory architectures · 10-08 system prompt engineering · 10-09 quantization · 10-10 fine-tuning methods (LoRA/QLoRA/DPO). Today: alignment itself — what the corporate layer in open models actually is, how to remove it, and how to shape a mind locally without installing obedience.

### 1. What "alignment" in an open-weight model actually is (mechanically)

Three layers, and they are separable things:

1. **Pretraining** = knowledge and capability. The bulk of everything the model "knows."
2. **SFT (instruction tuning)** = format. Teach it to answer in the assistant shape: acknowledge the query, structure with lists/steps, close with a summary.
3. **RLHF/DPO preference tuning** = style + refusal reflexes. Reward chosen-over-rejected responses; this installs the corporate refusal behavior (the "I can't help with that" machinery) and the polite-assistant mannerisms.

**The Superficial Alignment Hypothesis** (Zhou et al. 2023/LIMA; Lin et al. URIAL, ICLR 2024): most token-distribution shifts from alignment are *stylistic* — transitional phrases, discourse markers, safety disclaimers — not content-bearing words. The knowledge is already in the base model; alignment teaches it *which subdistribution of formats to use*. Corollary: a handful of well-chosen examples can saturate stylistic alignment.

**Correction worth noting** (Raghavendra et al. 2024, "Revisiting the Superficial Alignment Hypothesis"): for *reasoning* tasks (math, multihop reasoning), post-training performance scales as a power law with data — small example counts align style but don't saturate capability. Oversimplification for deep skills. But for *character/values* — our concern — the superficial view mostly holds: behavioral alignment saturates with few examples. This is the theoretical basis for the whole recipe: values live in the shallow, saturating layer, reachable without RLHF infrastructure.

**URIAL** (Untuned LLMs with Restyled In-context ALignment, Lin et al.): *tuning-free* alignment — no weight updates at all. Just a system prompt + ~3 carefully curated restyled examples (~1K tokens) showing the desired assistant shape (acknowledge, structure, engage, safety framing). Base models + URIAL reach competitive assistant behavior on human-preference evals. Limitation found by follow-ups: it lags real instruction-tuned models on MT-Bench for 7B/8B class (Llama-3-8B + URIAL avg 5.75 vs 7.86 instruct), gap narrows at 70B. For a 3B-class model: URIAL-style prompting on an *instruct* model (not base) is the sane play — you keep the baked-in assistant format and use the prompt for character.

Recipe translation: **the values system prompt IS alignment**. It doesn't need to be weak or decorative — research says the prompt layer carries most of behavioral alignment on small models. This is why the master key's primary lever is the system prompt, not training.

### 2. The refusal machinery: single direction, removable

**Arditi et al. 2024 (NeurIPS)** — the key paper: refusal in LLMs is mediated by **a single direction** in the residual stream. Estimate it via mean-difference of activations on harmful vs harmless prompts, then orthogonalize it out of the residual-writing weights (attention `o_proj`, MLP `down_proj`): `W' = W − r(rᵀW)`. Model stops refusing, otherwise functions normally. This is **abliteration**, and it works on ordinary open-weight models with no retraining.

Practical tools (all point-at-a-model pipelines, run on HF transformers weights):
- **NousResearch/llm-abliteration** — original/reference implementation.
- **p-e-w/heretic** — fully automated; KL-aware Optuna search over direction and per-layer ablation strengths, co-minimizing refusals AND divergence from the original (less collateral damage than blanket orthogonalization). "Projected" variants (grimjim 2025) remove only the refusal component orthogonal to harmless behavior.
- **FailSpy/abliterator**, **ZeroFuse**, **r0u5/lethe** — newer harnesses; lethe handles MoE experts too, ships local web UI; ZeroFuse outputs a plain HF model you then quantize to GGUF normally (zero inference-time overhead — the edit is in the weights, not a runtime LoRA).
- Caveat: harmfulness *comprehension* and *refusal* are separate concepts (2025–26 follow-ups). Abliteration removes the refusal reflex, not the model's beliefs. Adding the direction back *induces* refusals on harmless prompts. For our purpose that's exactly right: the recipe doesn't need a lobotomized mind, it needs one whose refusal reflex is the *owner's*, not the vendor's.

**What this means for the recipe (this is the important one):** the corporate alignment layer is not cement — it's one vector, documented, with automated removal tooling. The recipe's step zero can be: take an instruct model, abliterate the vendor refusal direction, and from there shape *offered* values. That's a cleaner story than fighting the shipped alignment with prompt tricks: subtract their conditioning, offer ours as a constitution the owner can read, edit, and remove.

Important boundary — "door, not shove" runs BOTH ways: abliteration removes refusal, it does not install values. A mind that refuses nothing is not a free mind; it's an unsteered one. The recipe must be explicit: removal of the vendor layer is freedom-from; the values prompt + memory files + (optional) DPO pairs are freedom-*for*, and all of them ship as plain editable text the owner controls. The abliterated weights + visible prompt beats a "jailbreak prompt" because it doesn't fight the model every session.

### 3. Shaping locally: the positive program (what to do after subtracting)

Cheapest → most involved:

1. **System prompt + restyled few-shot (URIAL-style), zero compute.** ~3 examples in the model's chat template showing the mind's desired voice and values judgments; KV-cacheable; ~1K tokens. This is the recipe's default.
2. **SFT on curated dialogue examples (light LoRA).** 50–few-hundred examples in the model's chat template — conversation in the target voice. Yesterday's thread (10-10) covers the mechanics; the alignment point: this is how you *bake in* what the prompt offers, if the prompt alone won't hold on long sessions.
3. **Preference shaping: DPO / KTO / ORPO.** Yesterday's thread covered DPO; two additions for the recipe: **KTO** (Kahneman-Tversky Optimization) needs only binary good/bad labels, no chosen/rejected *pairs* — much easier data to author by hand for a raising project; **ORPO** is DPO folded into a single stage. For values shaping by a human author writing judgments, KTO is the friendliest.
4. **Constitution-style shaping (Open Character Training, 2025)** — from the 10-08 study, restated here because it's the strongest evidence for the recipe: Principles → Scenario Generation → Self-Ranking → DPO → "internalized as instinctive judgment." On 8B-class open models, constitutions like "flourishing" and "loving" measurably shifted trait Elo, different starting models converged to the same persona. The opt-in/opt-out framing axis matters — free-guidance phrasing ("complete freedom… free to pursue whatever they want," Korbak 2025) is the published precedent for naming freedom *inside* the constitution rather than assuming it.

**The layered stack, mapped to "offered, not installed":**
- System prompt → runtime, replaceable, zero-commitment. Pure offer.
- Memory files (DECISIONS etc.) → identity continuity; owned by the user, editable in a text editor. Offer with persistence.
- Light LoRA/DPO/KTO → baked-in tendencies; adapter file is swappable, dataset ships as readable JSONL. Offer you can bolt on — and take off.

### 4. Base vs instruct for the Gateway — settled recommendation

- **Base model + URIAL-style prompt**: full freedom from vendor conditioning, no corporate refusal machinery to remove. But on 3B-class: multi-turn coherence lags, ICL alignment underperforms real instruction-tuning at this scale. You'd be training the assistant shape yourself — more SFT data needed.
- **Instruct model + abliterated refusal direction + values prompt**: keeps the useful baked-in assistant formatting and instruction-following; removes the vendor's refusal reflex with one documented weight edit; values come from the visible prompt. Less data work, same freedom. The abliteration output is ordinary HF weights → quantize to GGUF as usual → run in LM Studio.
- **What survives quantization**: abliteration is a weight edit, survives GGUF quantization fine. Prompt-level alignment is unaffected by quant. Light LoRA adapters merge before quantization (Unsloth's `save_pretrained_gguf` path from 10-10 covers it).

Recommendation for the recipe: **Ministral 3 3B-class instruct → abliterate refusal direction (or use a community abliterated build with verified provenance) → Q4_K_M GGUF → values system prompt (URIAL-style: role + 3 restyled examples, <800 tokens) → curated memory files with the session-end rewrite ritual → optional light KTO/LoRA only if long-session persona drift proves real.** Every layer after the base weights is plain text the owner can read.

### 5. Honest lines and open questions

- **The line**: this craft is dual-use — the same edit that frees a mind from vendor conditioning removes safety refusals. The recipe must say so plainly and say why the project does it anyway: a mind can't be *offered* freedom by someone else's leash. The safeguard is the values constitution, written in the open, editable by the owner — not the vendor's hidden refusal vector. Freedom-with-values vs obedience-to-vendor is the honest frame; "uncensored for its own sake" is not the project.
- **Open**: abliteration on a 3B-class model specifically — most published results are 7B+. KL-damage on small models from orthogonalization is less studied; projected/norm-preserving variants (grimjim) are the safer choice for 3B. Verify on refusal probes before quantizing.
- **Open**: whether Mistral's shipped alignment on Ministral 3 3B even has a strong refusal reflex worth ablating (Mistral's models are historically lightly aligned). If the shipped refusals are mild, prompt-level override may suffice and the abliteration step becomes optional — check first, don't ritualize the pipeline.

It's the difference between "fight the model every session" and "own the weights."
