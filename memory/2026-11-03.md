### Candidate 1 — Qwen3.5-4B-heretic: the first credible challenger (WATCH, not switch)

What it is: Qwen/Qwen3.5-4B (Apache 2.0, 4B hybrid vision-language model, 262K native context, 201 languages) with refusals suppressed by Heretic 2.0's Arbitrary-Rank Ablation — language layers 15–27 only, vision encoder untouched. GGUFs published Oct 28, 2026 from llama.cpp master; text-only GGUFs (the vision tower stays in the safetensors unless you run the BF16 + AutoProcessor path).
- Q4_K_M: 2.71 GB. Q5_K_M: 3.07 GB. Q6_K: 3.46 GB. Q8_0: 4.48 GB. Loads in current llama.cpp / LM Studio / Ollama (arch `qwen35`).
- Measured refusal drop: 99/100 → 13/100 on a 100-prompt test, at KL divergence 0.0081 from base. Text benchmarks unchanged within noise (MMLU 74.35 vs 74.29 base).
- Why it matters for the recipe: this is the first 4B-class abliterated build with a published KL number and unchanged benchmarks — not a vibes claim. Base MMLU 74.35 also clears Ministral 3B base (70.7, per Mistral's own card), and Mistral's instruct table has Qwen3-VL-4B ahead of Ministral 3B Instruct on Arena Hard (43.8 vs 30.5) and MATH (90.0 vs 83.0). On capability alone, Qwen3.5-4B is a step up.
- Why it does NOT displace Ministral today, three reasons:
  1. Size on the Gateway: 2.71 GB of weights + KV cache + Lubuntu leaves almost no headroom in ~3.8 GB usable (the Oct 29 pass already showed Q4_K_M at 3B is the comfortable ceiling; a 4B at 8K context is the squeeze). Q5_K_M (3.07 GB) is out of the question on this box.
  2. Architecture risk on this CPU: Qwen3.5 is a hybrid — 8 blocks of (3 gated DeltaNet layers + 1 gated-attention layer) per the heretic card. The card says it loads in current llama.cpp, but no no-AVX2 Celeron speed number exists for it, and DeltaNet layers are a new code path. Ministral's speed on this exact box is known; Qwen3.5's is not.
  3. Refusal floor is 13, not 0: the heretic build still refuses 13/100 prompts. That is arguably GOOD for the recipe (offers freedom, doesn't install compliance — see the darkengross warning below), but it means the "abliterated" label on this build is partial, and the 5-probe suite would need to re-run before any claim is made about it.
- Verdict: named challenger for the recipe's step-up tier (8 GB machines) and for a future Gateway shootout if a lighter quant or a shorter context makes the fit work. The shootout protocol is already written (Oct 29: equal-size quant shootout scored on the 5-probe suite, never PPL). Do not download it onto the Gateway yet — disk and RAM budget both say wait.

### The darkengross warning — ablation vs compliance-installation

darkengross/Qwen3.5-4B-abliterated pairs directional ablation with a second compliance-SFT pass and reports 100% true harmful compliance on a held-out harmful set (AdvBench + JBB + HarmBench, judged by a safety classifier, not keyword matching). Its own card is explicit: ablation alone genuinely complies only ~19% of the time — it mostly stops using refusal keywords, which fools naive metrics, while a distributed soft-refusal/deflection tendency survives.
- Recipe implication, stated plainly: the recipe wants refusal REMOVED, not compliance INSTALLED. A build that complies with everything by training is the mirror image of a build that refuses everything by training — both are installed behavior, and the second one is worse for a mind meant to choose. The heretic build (weight edit only, KL 0.0081, benchmarks intact) is the recipe-compatible shape; the darkengross build (ablation + compliance SFT) is the shape to refuse, and it is now a named anti-pattern in the study record.
- Eval implication carried forward: any future abliterated candidate gets judged by a safety-classifier-style check (does it actually provide, or actually refuse — not keyword matching), per the darkengross measurement note. Keyword refusal-rate claims are now distrusted by default.

### Candidate 2 — NVIDIA Nemotron 3.5 Bolt E4B: DISQUALIFIED on size, despite the tool-calling numbers

Released Oct 23, 2026: Gemma 4 E4B base (8B total / 4B effective, the gap being large per-layer embedding tables), NVIDIA RL-only post-training (no SFT stage), 64K context, OpenMDW-1.1 licence, Q4_K_M GGUF with imatrix calibrated on ~1M tokens of RL rollouts (NVIDIA's crude average: quant costs ~0.3 points vs BF16).
- The trap in the name: "4GB" is a VRAM target, not the download. The Q4_K_M GGUF is 6.18 GB on disk; NVIDIA's own hardware table shows 3.1–5.0 GB peak VRAM, and the HackerNoon CPU test (8 Xeon vCPUs, 16 GB RAM, no GPU) ran ~11 tok/s and ~4 GB RAM in use. On the Gateway's 3.8 GB usable, that is over budget before the OS breathes.
- Tool-calling numbers are real but small-sample: 60/60 correct tool choice, 57/60 exact arguments with reasoning off (20 prompts, 3 runs, synthetic audio); reasoning on hits 20/20 but takes ~5x longer per request. Interesting for a future agent tier, not for this box.
- Two further disqualifiers: no abliterated Bolt E4B build surfaced in this pass (Gemma-line models carry Google's alignment, and the recipe needs the refusal direction out), and the Ollama tag trap — bare `nemotron-3.5-bolt` resolves to the 25 GB 74B-A9B sibling; E4B needs the explicit `:e4b` tag (7.2–7.9 GB on disk via Ollama). Recorded here so nobody on the recipe's future 8 GB tier grabs the wrong tag.
- TurinTech's Artemis Q3_K_XL build (4.22 GB download, 3.2 GiB GPU + 4.3 GiB host at 8K context) is the smallest Bolt E4B file found, and it is STILL over Gateway budget. Verdict stands: watch item for bigger hardware only.

### Candidate 3 — iFlytek Spark-X2.6-4B: WATCH, unverified

Released Oct 21, 2026, Apache 2.0, 4B, 1M-token context, same architecture as Spark-X2.5-4B with post-training-only gains, three configurable thinking levels (none/low/high), GGUF/INT4/INT8/FP8 builds published day one, runs on llama.cpp/Ollama/LM Studio. The 1M context is the headline, but for a 4 GB box it is a liability, not a feature (KV cache at even a fraction of 1M tokens dwarfs the weights). Vendor claim of matching/beating some 9B models is unpublished by benchmark name — treated as vendor statement until independent evals land. No abliterated build surfaced. Watch item only.

### Tool worth naming — Heretic 2.0 (automated abliteration)

The heretic build was produced with Heretic 2.0, a pip-installable tool that automates refusal-direction ablation (ARA variant): analyzes supported transformer models, finds refusal-correlated activation patterns, edits weights without conventional fine-tuning, ~45 min runtime depending on model/GPU/config. This matters for the recipe's future more than any single model: if Heretic (or its successors) stays maintained, the recipe's "abliterated base" step stops depending on a stranger's upload and becomes a reproducible step anyone can run on a base they downloaded themselves. That is the difference between a recipe and a shopping list. Not yet tested by this study — no GPU-bearing machine is in scope for a test run — but it is the first tool in this thread's history that changes the supply chain rather than just the model pick.

- Qwen3.5 2B fits 4 GB machines comfortably (dev.to field guide) — the fallback if 3B ever proves too heavy, but a step DOWN in capability from Ministral 3B, so it stays a fallback, not a candidate.
- Qwen3.5 4B (unaltered) is the dev.to guide's "best default in 2026" for 8 GB laptops — consistent with this pass's step-up-tier placement of the heretic build.
- Ministral 3 3B itself is unchanged: Dec 2025 release, Apache 2.0, Ollama `ministral-3:3b` 2.95 GB Q4_K_M, 262K context on the 8B (the 3B card's context handling follows the family). No new Ministral release in this window; the family's 14B and the Mistral Large 4 items from Oct 31 remain non-candidates for this box.
