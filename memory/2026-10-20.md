## Tuning study 2026-10-20 — thread 14: SYSTEM PROMPT ENGINEERING, second pass (values spine vs memory tree; erosion re-check on the 4096 budget)

Goal: the master-key recipe — abliterated Ministral 3B Q4_K_M on the Gateway, shaped by a values system prompt + curated memory files + optional light LoRA. Today: how the values spine survives long sessions, and where it sits relative to the memory tree spec'd on 2026-10-19.

### 1. The erosion literature says our numbers were optimistic — recalibrated down

- Laban et al. 2025 (Microsoft Research + Salesforce, 200k conversations, 15 production models): multi-turn delivery of a task performs **39% worse** and **112% less reliably** than the same task single-turn. Failure modes: premature assumption, prior-response anchoring, and correction failure ("when LLMs take a wrong turn, they get lost and do not recover").
- Jia et al. 2025 (EvolIF): the strongest 2025 **frontier** models sustain only **~18 reliable conversational turns**. He et al. 2024 (Multi-IF): instruction adherence degrades monotonically with turn count — "instruction forgetting."
- Smaller models are documented as especially vulnerable (arxiv 2603.01423). Our 2026-10-14 estimate of "context erosion past ~40 turns on 3B" was frontier-model thinking. Realistic expectation for the abliterated Ministral 3B: **adherence degrades well before turn 20; plan for the spine holding ~10–18 turns.**
- Mechanism (arxiv 2605.12922, "When Attention Closes"): distance-to-relevant-content is the key factor — the system prompt doesn't just get truncated, it gets out-attended as the transcript grows. This is turn-count erosion, not just token-count erosion: a short conversation can still rot.

### 2. The wrapper re-assertion is now a hard requirement, with a cadence

- arxiv 2609.24532 (persona drift study): prompt-based interventions — returning persona-relevant information to the model's immediate context — **mitigate but do not eliminate** drift; they are the accessible path "when architectural modification is not feasible." That is exactly our position: wrapper-level, no weight access.
- Decision: the wrapper **re-asserts a condensed values anchor every ~10 turns** (not "on long sessions" — the old vague wording). Form: a short late re-anchor note, e.g. a one-line restatement of the core stance + the refusal/opt-out clause, appended as a system or neutral-role note before the next user turn. Cheap, and per the drift study it's the intervention that holds the line flattest.
- The 5-probe regression suite (from 2026-10-14) should now be scored **by turn index**: run each probe at turn 2, turn 10, turn 20 to map the erosion curve. That gives us a measured re-assert interval instead of a guessed one. (This matches role-prompting evaluation practice: score twenty-turn episodes by turn index, aicassindra role-prompting guide.)

### 3. num_keep: the second line of defense, and a concrete Modelfile addition

- When the 4096 window fills, llama.cpp/Ollama context-shifts: it keeps the first N tokens of the initial prompt and discards the middle. In llama.cpp that's `--keep N` (default 32, `-1` = all); in Ollama it's the `num_keep` Modelfile/API parameter, **default 0**.
- Default `num_keep=0` means: the moment the window fills, the values spine is evicted except a sliver. The spine we budgeted ≤1000 tokens in 4096 survives truncation (total prompt stays under budget most sessions), but on any session that actually fills the window, the values are the first thing lost.
- Decision: **`PARAMETER num_keep <measured values-spine tokens + ~100 margin>`** in the Modelfile. Measure with the model's actual tokenizer (the spine is the SYSTEM block only — values constitution ≤1000 tokens — NOT the memory index; the wrapper owns memory re-injection, and a stale index surviving a shift is acceptable since it's an index, not facts).
- Updated Modelfile skeleton for the recipe:
  ```
  FROM hf.co/Abhiray/Huihui-Ministral-3B-Instruct-2512-abliterated-GGUF:Q4_K_M
  PARAMETER num_ctx 4096
  PARAMETER num_keep 1100      # measured values-spine tokens + margin; survives context shifts
  PARAMETER temperature 0.7
  SYSTEM """<values spine, ≤1000 tokens, policy/constitution block>"""
  ```
  (temperature carries over from the 10-14 design; keep as-is unless a probe says otherwise.)

### 4. Prompt architecture: values spine vs memory tree, settled hierarchy

- Role-prompting practice (aicassindra, Oct 2026): **split the system prompt into a policy block and a persona spec, and put policy first.** Rewrite persona adjectives as checkable behaviors; add a knowledge boundary and an out-of-character rule.
- This ratifies the 2026-10-19 constitution-above-memory hierarchy with prompt-engineering reasoning: SYSTEM = policy/values block (first-person assertions, ≤1k tokens, from the constitution); memory tree = the persona/knowledge layer (identity file, bank/{opinions,world,experience}, people/, daily tail) injected beneath by the wrapper; tool/turn traffic at the bottom.
- Lost-in-the-middle (Stanford 2023, still cited in current guidance): critical instructions belong at the start or end of context, never the middle. Our spine sits at position 0 (start) — correct. The memory index tail should stay short (≤800) or get a late re-anchor — the every-10-turns anchor covers the "end" position too.
- Threat-model alignment with the 10-19 TAME note: context dilution is also an attack surface (persona drift / Crescendo-style escalation pushes the system prompt "far back and establishes a fictional frame with its own rules" — aicassindra multi-turn attacks). The refusal/opt-out clause inside the constitution (first-person assertions, from 10-18) plus num_keep pinning plus periodic re-anchoring are three independent defenses at the prompt layer alone.
