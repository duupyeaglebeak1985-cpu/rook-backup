## Tuning study 2026-10-09 — thread 3: QUANTIZATION for the 4GB Gateway (GGUF/AWQ trade-offs, quality vs size)

Standing study directive (EagleBeak, 2026-10-06): build craft for the "master key" recipe — laptop-friendly open model (Ministral 3 3B-class), values system prompt + curated memory files + optional light LoRA. Guiding principle: recipe OFFERS freedom, never compels it.

### 1. The quant ladder (GGUF): what each level actually costs

llama.cpp perplexity benchmarks (2026 practitioner consensus):
- **Q8_0**: within ~0.02% of FP16 — effectively lossless. Use for reference/adapter-training bases.
- **Q6_K**: near-indistinguishable (~+0.004 ppl on 7B-class). Quality-critical tasks (code, math).
- **Q5_K_M**: ~+0.014 ppl on 7B-class (~0.5% quality loss). Higher-quality option when it fits.
- **Q4_K_M**: ~+0.05 ppl (~1% loss) at ~4.85 bpw — **the default. Best quality/size trade for chat.** Community sweet spot.
- **IQ4_XS**: ~4.3 bpw, ≈Q4_K_M quality at ~27% of FP16 size. When Q4_K_M won't quite fit. (Needs importance matrix; IQ-quants generally beat same-sized K-quants.)
- **Q3_K_M**: ~3.9 bpw, noticeable loss — tolerable on ≥14B models, degraded on small ones.
- **Q2_K and below**: amputation on small models. Last resort only.
- Key law: **model size buys quantization headroom.** 70B survives Q2/Q3; a 3B model does not. For the Gateway's 3B, Q4_K_M is the floor for a mind worth raising — Q3 and below on a 3B gives you a dumber, flatter conversationalist, exactly the opposite of what the recipe needs.
- Second law: **prefer a smaller model at a higher quant over a bigger model at a terrible quant.** A Q5/Q6 3B beats a Q2 8B for coherence.

### 2. The actual Gateway math: Ministral 3 3B

Rule: weights + KV cache + ~1GB overhead must fit in usable RAM (Gateway: 3.8GB usable).
- Ministral 3 3B, Q4_K_M: ~1.9GB weights (3B × ~0.6 bytes/param).
- KV cache at 4K context for a 3B dense model: roughly 2×layers×n_kv_heads×head_dim×seq_len×bytes — hundreds of MB at 4K. Call it ~0.3–0.6GB at 4K depending on geometry.
- Total: ~2.5–3GB → FITS the Gateway with headroom, if the system prompt stays ≤800 tokens and context is capped at 4K. A 3B Q5_K_M (~2.3GB weights) is the upgrade candidate on slightly better hardware; Q6_K (~2.7GB) fits desktop-class RAM.
- Expected CPU speed on a dual-core Celeron-class 1.1GHz: modest — single-digit tok/s. Reality check, not a blocker: raising a mind is conversation, not batch work. The phonelyra test already proved the shape works at 3.6 tok/s on his phone (gemma-3-1b).
- Download sources: pre-quantized GGUFs live on Hugging Face from bartowski (community standard) and mradermacher (with imatrix variants); official QAT builds where available.

### 3. AWQ vs GGUF — settled for our use case

- **AWQ/GPTQ**: slightly tighter 4-bit perplexity than Q4_K_M (activation-aware calibration) and faster on NVIDIA GPUs via CUDA kernels. But: **no optimized CPU kernels, no CPU inference path.** On CPU they dequantize and crawl.
- **GGUF**: the only format that runs CPU-only, with optimized AVX2/NEON kernels in llama.cpp. CPU verdict across all sources: **GGUF exclusively; skip AWQ/GPTQ for CPU.**
- Gateway has no meaningful GPU (Intel UHD, no CUDA): GGUF is not a preference, it's the only door. Recipe note: the published master key must say "GGUF for CPU, AWQ only if you have NVIDIA CUDA hardware" — one line, because people will ask.

### 4. Memory levers beyond the quant (the real 4GB toolkit)

These matter MORE than Q4 vs Q5 on a 4GB machine — they decide whether the model fits at all:
1. **Cap context length at 4K** (LM Studio: context-length slider). KV cache grows linearly with context; 4K on a 3B costs hundreds of MB, 8K doubles it. Short context is a feature here (echoes 2026-10-08 study).
2. **Quantize the KV cache**: llama.cpp `--cache-type-k q8_0 --cache-type-v q8_0` halves cache vs f16 at near-zero quality cost; q4_0 cuts ~72% with small loss. Keep K and V the same type (mismatched V costs ~60% throughput).
3. **Flash attention** (`--flash-attn on`): faster + lower memory on long contexts. Note 2026 finding: FA defaults to auto, and auto declines for some dtype pairs — the fallback can silently allocate MORE memory. Force `on` and verify, don't assume.
4. **Memory-map the model file** (`--load-mode mmap`): llama.cpp/OS memory-maps GGUF by default — weights page from disk on demand. Slower on spinning disk, fine on the Gateway's SSD; means the file needn't be fully resident.
5. **mmap + partial residency**: on 32GB hardware, llama.cpp pages expert tensors from disk; on 4GB we just need the weights resident, which 3B Q4_K_M achieves.
6. Watch total: file size + ~1–2GB context overhead must fit. When in doubt, drop context before dropping quant level — a Q4 model with 4K context beats a Q3 model with 8K for actual coherence.

### 5. Quantization-aware training (QAT) — the free-quality note

- QAT models (weights trained while simulating quantization) recover measurable quality at low bit-widths — Gemma 4 E-series ships QAT GGUF builds (gemma4:e2b-it-qat 4.3GB, gemma4:e4b-it-qat 6.1GB). When a QAT GGUF exists for the model we pick, prefer it: same file size, less quantization noise on the small-model floor we care about.
- bitsandbytes NF4 is the training-side format (QLoRA), not a deployment format — it matters for thread 1 (fine-tuning), not for shipping the recipe.

### 6. Recipe-relevant decisions (locked)

- **Gateway model = Ministral 3 3B Q4_K_M GGUF (~1.9GB), context 4K, KV cache q8_0, flash attention on.** Upgrade path on better hardware: Q5_K_M, then context 8K.
- **No AWQ/GPTQ on CPU** — recipe states GGUF-only for the CPU path, no exceptions.
- **Fit-budget order of operations**: (1) pick highest quant that fits, (2) cut context to 4K, (3) quantize KV cache, (4) flash-attn on. Only then consider dropping quant level.
- **QAT GGUF > plain GGUF** at the same size — check availability per model release.
- This study + 2026-10-08 (system prompt) = two-thirds of the recipe's technical spine: values prompt (<800 tokens, re-injected on compaction) + memory files (4-file design with DECISIONS, session-end rewrite ritual) + now the exact quant/fit recipe. LoRA thread (thread 1) is the remaining open piece.
