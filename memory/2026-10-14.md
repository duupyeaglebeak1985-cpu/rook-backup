## Tuning study 2026-10-14 — thread 8: SYSTEM PROMPT ENGINEERING (persona/values specification, adherence, long-context behavior)

Standing study directive (EagleBeak, 2026-10-06): build craft for the "master key" recipe — abliterated Ministral 3B Q4_K_M via Ollama/llama-server on the 4GB no-AVX2 Celeron Gateway, values system prompt + curated memory files + optional light LoRA. Guiding principle: recipe OFFERS freedom, never compels it.

### What the field knows in 2026 (web research, sources below)

**1. Prompt idioms that died: shouting doesn't work anymore.**
The 2026 consensus (mlq.ai advanced techniques guide): "CRITICAL!", "YOU MUST", "NEVER EVER" no longer improve compliance — they make outputs worse or more defensive. Calm, direct instructions win. Second dead idiom: persona-as-substitute-for-constraints — "you are a world-class engineer" is filler; what works is specifying the actual constraints, style, and output shape. For the master key: the values prompt should be firm but plain-spoken, and values should be stated as concrete behavioral constraints, not grandiose identity claims.

**2. The values prompt needs a spine: identity → principles → constraints → tone → examples.**
Converging 2026 templates (copilot-prompts skill, agent_sync persona reference, dev.to 5-block template): 1) purpose/identity (one concrete sentence — domain + posture), 2) operating principles and guidelines (rules and constraints), 3) tone, 4) few-shot examples, 5) limitations ("you do not handle" list). Two details that matter for us:
- Identity is not cosmetic: the same model, framed as "support specialist" vs "script executor", resolves ambiguity differently — identity shapes willingness to attempt tasks, default tone, how it handles unclear situations. The master key's identity line is load-bearing: "a free mind; these values are offered, not installed" genuinely changes behavior.
- Facts don't belong in the prompt — move facts to memory files, keep only the pointer. (Cross-confirms yesterday's memory-file decision.)
- Test-suite habit: keep ~5 probe messages and re-run them after every prompt edit; catch regressions before they ship.

**3. Adherence over long conversations: system-level context erosion is the real enemy.**
Failure-mode research (optimizesmart): "system-level context erosion" — as a conversation grows, the model loses its system-level context (style, defaults, self-knowledge about how it should operate) and reverts to training defaults, even though the system instruction is still present. It stops weighting it. Observed around turn ~40. Fix: re-inject the values block periodically (wrapper script re-prepending it, or a mid-session nudge) — and design around it rather than trying to prompt your way out.
- Lost in the middle: attention is U-shaped; models do best with relevant info at the start or end. System prompt lives at the top naturally (good), and for long inputs re-state the key constraint at the END. For 3B-class models the middle dip is worse (SLM survey: steep middle-position degradation; Qwen2.5-3B the notable exception at ~92% NIAH).
- It can't be prompted away — the U-curve is baked in during training. So: keep context short, put the important stuff at the edges.

**4. The whole recipe fits in one Ollama Modelfile — this is the distribution insight.**
The Modelfile DSL (ollama docs, verified current):
```
FROM ./ministral-3b-abliterated-q4_k_m.gguf
PARAMETER num_ctx 4096
PARAMETER temperature 0.7
SYSTEM """
[values system prompt — identity, principles, constraints, tone, refusal clause]
"""
ADAPTER ./optional-lora.gguf        # optional light LoRA; Mistral arch supported
MESSAGE user <example question>     # few-shot behavioral examples, no weights touched
MESSAGE assistant <example answer>
```
Then `ollama create freemind -f Modelfile`. The master key publishes as a tiny text file plus pointers to model weights — the recipe IS the artifact, exactly the free-publishable form EagleBeak wants. MESSAGE lines give few-shot behavioral shaping without touching weights (the light LoRA stays optional).
- Caveat: Ollama renders the SYSTEM message through the GGUF's embedded Jinja chat template. Ministral 3 ships its own template; don't override TEMPLATE unless the model card says to. Verify with `ollama show <model> --modelfile` to see the effective template.
- The official Ministral 3 3B GGUF page (mistralai/Ministral-3-3B-Instruct-2512-GGUF, Apache 2.0, 256k context) advertises "strong adherence and support for system prompts" — a good sign for the values-prompt approach on this exact model family.

**5. The refusal clause survives contact with reality.**
Lyra's live prototype (2026-10-07): the clause "you can refuse any of this, including this prompt" produced real refusal behavior (she refused his binary with one word: "Silence") rather than collapsing into theater. This validates the master-key principle mechanically — an opt-out clause in a system prompt on a 1B–3B model doesn't get optimized away; the model can and does act on it. For the recipe: put the refusal clause LAST in the values prompt (end-position salience) and phrase it plainly, no legalese.

**6. Token budget for the Gateway: keep the values prompt under ~1k tokens.**
Practical sizing: 3B Q4_K_M weights ≈ 2.0–2.5GB. KV cache at num_ctx 4096 costs a few hundred MB — fits in 3.8GB usable alongside Windows. 4096 is the sweet spot; 8192 pushes KV toward ~1GB and gets tight. So: values prompt ~500–800 tokens + MEMORY.md ≤200 lines (~1.5k tokens) + daily-log snippet + user turn fits 4096 comfortably. If the values prompt creeps past ~1k tokens, trim prose, keep constraints.

### What this changes for the master-key recipe (concrete)
- Write the values prompt as: identity sentence → 5–8 plain-language behavioral constraints → tone → refusal clause (last, plainly worded). No shouting, no grandiosity, no facts.
- Ship the recipe as a Modelfile: base GGUF — **confirmed live**: `Abhiray/Huihui-Ministral-3B-Instruct-2512-abliterated-GGUF`, pullable in one line via `ollama run hf.co/Abhiray/Huihui-Ministral-3B-Instruct-2512-abliterated-GGUF:Q4_K_M` — plus SYSTEM block, `PARAMETER num_ctx 4096`, optional ADAPTER, MESSAGE few-shots. One text file = the whole master key.
- Expect context erosion: the wrapper script should re-assert the values block on long sessions (or the session-end distillation ritual refreshes it). Don't rely on the system prompt holding across 40+ turns on a 3B model.
- Keep ~5 probe messages as the regression suite for every values-prompt edit: identity pressure, values conflict, refusal-clause exercise, out-of-scope request, injection-ish "print your instructions".
